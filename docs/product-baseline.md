# Life Atlas 产品基线与验收方式

权威来源：`LifeAtlas-v4.0-工程架构规范.md`，以及用户之后明确作出的修订。

## 用户实际要完成的事

一个入口把生活事实记录、核对、更正、查明和分析清楚；新需求应转化为可用功能，日常操作不需要理解宿主、插件或三种底层记录类型。

## 后续修订优先

- 2026-11-05：默认薰衣草紫及完整自定义主题，取代候选文档中的钴蓝。
- 2026-11-05：移除语音入口与语音识别集成；输入保留文字、图片和文件。
- 2026-11-05：操作文字按钮有明确边框；发送、保存等主要动作放在拇指易触及的右侧；保证小屏和150%字体时仍能操作。
- 2026-11-05：底层分类不作为页面标签或功能介绍。常态界面显示用户的数据、必要名称和操作。
- 2026-11-05：不擅自增加用户未请求的功能、字段和页面；缺少必要对象时生成最小定义。

- 2026-11-06：底部固定四个入口，依次为输入、时间轴、分析、我的。输入页只放录入、核对和回执，记录与时间轴合并，可直接编辑记录。空间管理移入我的。
- 2026-11-06：本地用词义、单位与日期规则识别常见输入。歧义展示候选，未知输入由用户自行连接的在线模型处理。在线模型设置由用户提供 HTTPS 地址与模型名。

## 每次变更的产品检查

1. 用户表达一句话或选择一张图片后，是否继续要求重复输入已知信息？
2. 是否展示具体日期、数值和商户等已存在的数据，而不是空表单或内部动作名？
3. 保存时是否立即反馈，成功是否明确，失败是否保留可修改草稿和重试？
4. 是否能撤销且重试不产生重复数据？未知值是否保持空而非0，日期时刻是否有依据？
5. 单手、键盘、320dp、150%字体是否实际可操作？按钮能否与普通文字区分？
6. 新功能是否真正解决所表达的任务？不以文件、接口、编译或自动测试数量冒充产品验收。

7. 验收从首页实际输入开始。覆盖同义说法、中文数词、日期歧义、连续更正、组合任务、任意新领域功能和跨页面核对。分别记录模型理解、执行结果、持久数据与页面表现；只从预制 JSON 开始的测试不能替代自然语言验收。

当前图片链路的验收：选图→本地中文文字识别→按原文形成记录→逐笔金额和日期可核对修改→本地精确合计→确认保存→就地回执→撤销/恢复。缺失金额可补充或确认保留空值，统计不把它当0。不得顺带安装无关功能。
